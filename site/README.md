# آموزش سیلانه‌سبز — نسخه‌ی ساده

وب‌سایت آموزش محصولات برای بازاریاب‌های سیلانه‌سبز.
**کاملاً رایگان، بدون کارت بانکی، بدون R2، بدون Firebase.**

---

## ۱. معماری — چه چیزی کجاست

```
                    ┌──────────────────────────────┐
   کاربر            │      GitHub Pages            │   فایل‌های سایت (HTML/JS/CSS)
   ────────►        │  https://user.github.io/repo │   + لوگو و تصویر ۲۳۸ محصول
                    └───────────────┬──────────────┘
                                    │  درخواست /api
                                    ▼
                    ┌──────────────────────────────┐
                    │   Cloudflare Worker          │   کد سمت سرور
                    │   ssl-api.<you>.workers.dev  │   (ورود، کاتالوگ، آزمون، گزارش)
                    └───────────────┬──────────────┘
                                    ▼
                    ┌──────────────────────────────┐
                    │   Cloudflare D1              │   دیتابیس
                    │   ssl-db                     │
                    └──────────────────────────────┘
```

**نکته‌ی مهم:** GitHub Pages فقط فایل ثابت سرو می‌کند و نمی‌تواند مستقیم به D1 وصل شود.
به همین دلیل سایت دو تکه است: فایل‌ها روی گیت‌هاب، داده‌ها روی کلودفلر.
اتصال این دو با یک آدرس اینترنتی است (`VITE_API_BASE`).

ویدئو و پادکست **لینک** هستند (یوتیوب، آپارات، یا آدرس مستقیم فایل)،
چون R2 نیاز به کارت بانکی دارد. تصاویر محصولات روی خود GitHub Pages سرو می‌شوند.

| تکه | سرویس | پلن |
|---|---|---|
| سایت | GitHub Pages | رایگان |
| API | Cloudflare Workers | رایگان (۱۰۰٬۰۰۰ درخواست در روز) |
| دیتابیس | Cloudflare D1 | رایگان (۵ گیگابایت) |
| تصویر محصولات | GitHub Pages | رایگان |
| ویدئو/پادکست | یوتیوب / آپارات / لینک مستقیم | رایگان |

---

## ۲. پیش‌نیازها

- **Node.js نسخه‌ی ۲۰ یا بالاتر** — بررسی: `node -v`
- یک **اکانت کلودفلر** (رایگان، بدون کارت)
- یک **ریپوی گیت‌هاب** که همین کد در آن باشد

---

## ۳. راه‌اندازی — ۱۰ قدم

> همه‌ی دستورهای زیر را داخل پوشه‌ی `site/worker` اجرا کنید،
> مگر آن‌هایی که نوشته شده `site/web`.

### قدم ۱ — ورود به کلودفلر

```bash
cd site/worker
npm install
npx wrangler login
```
مرورگر باز می‌شود؛ اجازه بدهید و برگردید.

### قدم ۲ — ساخت دیتابیس D1

```bash
npm run db:create
```
خروجی چیزی شبیه این است:
```
[[d1_databases]]
binding = "DB"
database_name = "ssl-db"
database_id = "a1b2c3d4-....-...."     ← این را لازم داریم
```

**`database_id` را در فایل `wrangler.jsonc` جایگزین `REPLACE_WITH_YOUR_D1_DATABASE_ID` کنید.**

### قدم ۳ — ساخت جدول‌ها

```bash
npm run db:migrate:remote
```

### قدم ۴ — گذاشتن دو Secret

```bash
npx wrangler secret put AUTH_SECRET
```
یک متن طولانی و تصادفی وارد کنید (مثلاً خروجی `openssl rand -hex 32`).
این کلید امضای توکن ورود است؛ **هرگز آن را در جایی منتشر نکنید.**

```bash
npx wrangler secret put ADMIN_PHONE
```
شماره‌ی موبایل خودتان، مثلاً `09121234567`.
هر کس با این شماره وارد شود، پنل مدیریت را می‌بیند.
برای چند مدیر، با ویرگول جدا کنید: `09121234567,09127654321`

### قدم ۵ — انتشار Worker

```bash
npm run deploy
```
در پایان یک آدرس می‌بینید:
```
https://ssl-api.<زیردامنه‌ی شما>.workers.dev
```
**این آدرس را یادداشت کنید** — در قدم ۸ لازم است.

### قدم ۶ — وارد کردن کاتالوگ

```bash
npm run seed:remote
```
۱۲ برند و ۲۳۸ محصول واقعی سیلانه‌سبز وارد می‌شود.
این دستور تکرارپذیر است؛ چند بار اجرا کردنش رکورد تکراری نمی‌سازد.

### قدم ۷ — تست اینکه API کار می‌کند

```bash
curl https://ssl-api.<زیردامنه‌ی شما>.workers.dev/api/health
```
باید ببینید: `{"ok":true,"time":"..."}`

### قدم ۸ — معرفی آدرس API به سایت

در ریپوی گیت‌هاب:
**Settings → Secrets and variables → Actions → Variables → New repository variable**

| نام | مقدار |
|---|---|
| `VITE_API_BASE` | `https://ssl-api.<زیردامنه‌ی شما>.workers.dev/api` |

دقت کنید که `/api` در آخر باشد و `/` اضافه نگذارید.

### قدم ۹ — فعال کردن GitHub Pages

در ریپو:
**Settings → Pages → Build and deployment → Source: `GitHub Actions`**

سپس یک بار کد را به شاخه‌ی `main` پوش کنید (یا در تب Actions، ورک‌فلوی
«سایت — تست و انتشار» را با `Run workflow` اجرا کنید).

بعد از چند دقیقه سایت اینجاست:
```
https://<نام‌کاربری>.github.io/<نام‌ریپو>/
```

### قدم ۱۰ — (اختیاری) دامنه‌ی اختصاصی

۱. در **Settings → Pages → Custom domain** دامنه‌ی خود را بنویسید (مثلاً `learn.seylanesabz.ir`).
   گیت‌هاب یک فایل `CNAME` می‌سازد.
۲. در **Cloudflare → DNS** این رکوردها را اضافه کنید:

| Type | Name | Content | Proxy |
|---|---|---|---|
| A | `learn` | `185.199.108.153` | **DNS only** (ابر خاکستری) |
| A | `learn` | `185.199.109.153` | **DNS only** |
| A | `learn` | `185.199.110.153` | **DNS only** |
| A | `learn` | `185.199.111.153` | **DNS only** |

> ⚠️ **ابر حتماً خاکستری (DNS only) باشد.** اگر نارنجی (Proxied) باشد،
> GitHub Pages کار نمی‌کند. این رایج‌ترین اشتباه است.

۳. در Settings → Pages تیک **Enforce HTTPS** را بزنید.

## ۴. بعد از بالا آمدن — اولین کارها

### الف) خودتان وارد شوید

۱. سایت را باز کنید → **ثبت‌نام** → نام، نام خانوادگی و همان شماره‌ای که در `ADMIN_PHONE` گذاشتید.
۲. حالا در نوار بالا آیکون سپر (پنل مدیریت) را می‌بینید.

### ب) افزودن محتوای اولین محصول

در پنل مدیریت:

1. **آزمون‌ها** ← «ساخت آزمون» ← عنوان، حد نصاب (مثلاً ۷۰٪)، سؤال‌ها و گزینه‌ها.
   گزینه‌ی درست را با پر کردن دایره‌ی کنارش مشخص کنید.
2. **محتوا** ← برند و محصول را از دو فهرست بالا انتخاب کنید.
3. «افزودن محتوا»:
   - **پادکست** → نوع را «پادکست» بگذارید، عنوان بدهید و لینک فایل صوتی را بچسبانید.
   - **ویدئو** → نوع را «ویدئو» بگذارید و لینک یوتیوب یا آپارات را بچسبانید.
   - **آزمون** → نوع را «آزمون» بگذارید و آزمونی که ساختید انتخاب کنید.

### چه لینک‌هایی کار می‌کنند؟

| نوع | نمونه |
|---|---|
| یوتیوب | `https://www.youtube.com/watch?v=XXXX` یا `https://youtu.be/XXXX` |
| آپارات | `https://www.aparat.com/v/XXXX` |
| فایل صوتی مستقیم | `https://.../file.mp3` (یا m4a, ogg, wav) |
| فایل ویدئویی مستقیم | `https://.../file.mp4` (یا webm) |
| هر لینک دیگر | به‌صورت دکمه‌ی «باز کردن در صفحه‌ی جدید» نشان داده می‌شود |

> برای آپلود فایل صوتی/ویدئویی بدون هزینه، می‌توانید از سرویس‌های رایگان
> مثل آرشیو خود آپارات یا یوتیوب استفاده کنید و فقط لینکش را بدهید.

### پ) دیدن وضعیت بازاریاب‌ها

پنل مدیریت ← **بازاریاب‌ها**:
- درصد پیشرفت هر نفر، آخرین فعالیت، میانگین آزمون
- با کلیک روی هر نفر: کدام محتوا را کامل کرده، کدام را نصفه‌کاره رها کرده
- دکمه‌ی **«خروجی اکسل»** یک فایل CSV می‌دهد که در Excel فارسی درست باز می‌شود

## ۵. اجرای محلی (برای تست روی کامپیوتر خودتان)

```bash
# از پوشه‌ی site
cd worker && npm install && npm run db:migrate:local && npm run seed:local
cp .dev.vars.example .dev.vars      # فقط برای اجرای محلی
cd .. && node scripts/serve-all.mjs
```
سایت روی `http://localhost:5173` بالا می‌آید.
ادمین محلی: شماره‌ی `09120000001`

---

## ۶. تست‌ها

```bash
# API — typecheck + ۷۷ بررسی روی Worker واقعی و D1 واقعی
cd site/worker && npm test

# بیلد سایت + بررسی اینکه زیر زیرمسیر (مثل GitHub Pages) درست کار می‌کند
cd site/web && npm run build && npm run check:dist

# تست در مرورگر واقعی روی موبایل و دسکتاپ (Pixel 7، iPhone 13، دسکتاپ)
cd site/web && npx playwright install && npm run test:browser
```

هر سه در GitHub Actions هم به‌صورت خودکار اجرا می‌شوند و
اگر چیزی خراب باشد، **سایت منتشر نمی‌شود**.

## ۷. عیب‌یابی

| مشکل | علت و راه‌حل |
|---|---|
| سایت سفید است | `VITE_API_BASE` تنظیم نشده یا غلط است. باید دقیقاً `https://ssl-api...workers.dev/api` باشد. |
| «اتصال برقرار نشد» | آدرس Worker غلط است یا Worker منتشر نشده. `curl .../api/health` را امتحان کنید. |
| خطای CORS در کنسول مرورگر | در `wrangler.jsonc` مقدار `ALLOWED_ORIGINS` را به دامنه‌ی سایت خود تغییر دهید و دوباره `npm run deploy`. |
| پنل مدیریت را نمی‌بینم | شماره‌ی شما در `ADMIN_PHONE` نیست. دوباره `npx wrangler secret put ADMIN_PHONE` و سپس **خروج و ورود مجدد**. |
| ورود می‌گوید «این شماره ثبت نشده» | اول باید **ثبت‌نام** کنید، نه ورود. |
| تصویر محصولات نمی‌آید | `npm run sync-assets` را اجرا کرده‌اید؟ در بیلد CI خودکار انجام می‌شود. |
| GitHub Pages 404 می‌دهد | Source روی `GitHub Actions` باشد، نه `Deploy from a branch`. |
| دامنه‌ی اختصاصی کار نمی‌کند | ابر کلودفلر باید **خاکستری (DNS only)** باشد. |

---

## ۸. تغییر دادن `ALLOWED_ORIGINS` (پیشنهاد امنیتی)

به‌صورت پیش‌فرض `*` است تا راه‌اندازی ساده باشد. بعد از بالا آمدن سایت،
در `wrangler.jsonc` بنویسید:

```jsonc
"vars": {
  "ALLOWED_ORIGINS": "https://<user>.github.io,https://learn.seylanesabz.ir"
}
```
و دوباره `npm run deploy`.

## ۹. ساختار پوشه‌ها

```text
site/
  worker/               بک‌اند (Cloudflare Workers + D1)
    schema.sql          ساختار دیتابیس
    seed.mjs            وارد کردن ۱۲ برند و ۲۳۸ محصول
    wrangler.jsonc      تنظیمات کلودفلر
    src/index.ts        مسیرها و مسیریابی
    src/auth.ts         ورود، توکن، نقش ادمین
    src/catalog.ts      خواندن برندها/محصولات/محتوا
    src/learning.ts     ثبت پیشرفت و تصحیح آزمون
    src/admin.ts        CRUD ادمین و گزارش‌ها
    test/e2e.mjs        ۷۷ بررسی روی Worker واقعی
    test/run-e2e.mjs    اجراگر: دیتابیس تمیز → seed → Worker → تست
  web/                  سایت (GitHub Pages)
    src/pages/          صفحه‌های ورود، ثبت‌نام، برندها، محصول، آزمون، ادمین
    src/components/     اجزای مشترک
    scripts/sync-assets.mjs   کپی لوگوها و ۲۳۸ تصویر محصول
    e2e/                تست مرورگر واقعی
  scripts/
    serve-all.mjs       بالا آوردن Worker و سایت با یک دستور
    check-dist.mjs      بررسی بیلد زیر زیرمسیر
```
